# 实验 2 操作卡：第一次亲自验收

这张操作卡只包含你必须亲自完成的步骤。项目代码、测试和网页已经准备好。

## A. 先安装 WSL 与 Ubuntu

当前电脑尚未启用 WSL 系统功能，需要用管理员权限完成一次安装。

1. 在开始菜单搜索“终端”。
2. 右键“终端”，选择“以管理员身份运行”。
3. 输入：

```powershell
wsl --install --web-download
```

4. 如果系统要求重启，保存其他工作后重启电脑。
5. 重启后首次打开 Ubuntu，按提示创建 Linux 用户名和密码。
   - 输入密码时终端不会显示字符，这是正常现象。
   - 用户名和密码请自行保存，不要放入实验截图或发给 AI。

建议截图：

- 管理员终端执行安装命令后的成功结果；
- Ubuntu 首次启动并成功进入命令行的界面；
- `wsl -l -v` 显示 Ubuntu 和 VERSION 2 的结果。

## B. 将项目放入 WSL

WSL 安装完成后再执行。项目当前位于 Windows 工作区，后续会将它复制到 Linux 家目录中，以避免跨系统读写带来的额外开销。

这一步暂时不要自行复制；确认 WSL 安装成功后，由 Codex 根据你的 Ubuntu 用户名生成准确命令。

## C. 第一次 Git 提交

项目进入 WSL 后，在项目目录执行：

```bash
git init
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
git add .
git status
git commit -m "feat: create explainable job matching MVP"
git log --oneline
```

建议截图：

- `git status` 显示准备提交的文件；
- 第一次 `git commit` 成功；
- `git log --oneline` 显示提交记录。

## D. 运行项目与测试

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest -q
python app.py
```

浏览器访问：`http://localhost:8000`

建议截图：

- `3 passed` 的测试结果；
- 项目首页；
- 输入经历和 JD 后生成的匹配结果页。

## 本阶段你需要理解的 5 个问题

1. 为什么项目建议放在 WSL 的 Linux 目录，而不是 `/mnt/c` 或 `/mnt/e`？
2. `git add` 和 `git commit` 分别做了什么？
3. 为什么 `.venv` 和 `.env` 不应该提交到 Git？
4. 当前匹配分数为什么只能称为可解释基线，而不能称为录用概率？
5. 为什么测试通过比“网页看起来正常”更可靠？
