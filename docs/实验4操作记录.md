# 实验 4：AI Coding 操作记录

## 一、实验目标

在 AI Job Copilot 项目中使用 OpenCode 完成 Agent 驱动开发，并验证测试驱动调试、自定义 Skill、项目 Agent、MCP 工具和分级权限控制。

## 二、实验环境

- 操作系统：Windows 11 + WSL 2（Ubuntu）
- 项目：AI Job Copilot（Flask + pytest）
- OpenCode：1.18.35
- Python：3.11+
- 代码仓库：`dazzlingn716/ai-job-copilot`

OpenCode 安装在 `/home/ariella/.opencode/bin/opencode`，并通过 `/usr/local/bin/opencode` 调用。由于当前 WSL 环境不支持普通 x64 构建，实验使用官方 `opencode-linux-x64-baseline` 包；安装后执行 `opencode --version`，输出 `1.18.35`。

## 三、Agent 驱动的测试与调试

### 1. 暴露缺陷

为匹配器新增测试 `test_compact_ai_product_keyword_is_recognised`。测试输入使用没有空格的“AI产品设计”，期望同时识别“AI 产品设计”和“需求分析”。

第一次运行 pytest 得到：

```text
1 failed, 3 passed
```

失败输出保存在 `docs/实验4-失败测试.txt`，失败阶段提交为 `908e041`。

### 2. 按调试闭环处理

按照自定义 Skill 规定的 Observe → Hypothesize → Plan → Execute → Verify 流程进行：

1. Observe：实际结果缺少“AI 产品设计”；
2. Hypothesize：别名表只有带空格的 `ai 产品`，无法识别 `AI产品`；
3. Plan：保留回归测试，只补充紧凑别名；
4. Execute：在 `SKILL_ALIASES` 中加入 `ai产品`；
5. Verify：重新运行全部测试。

修复后输出：

```text
4 passed in 0.02s
```

通过输出保存在 `docs/实验4-通过测试.txt`，修复提交为 `6b3b541`。完整分析见 `docs/实验4-调试过程.md`。

## 四、自定义 Skill

创建 `.opencode/skills/debug-workflow/SKILL.md`，将调试流程封装为项目 Skill。执行 `opencode debug skill` 后，OpenCode 能发现 `debug-workflow`，说明 Skill 已正确加载。

同时创建 `/test` 命令，使 Agent 加载该 Skill 后运行：

```bash
.venv/bin/python -m pytest -q
```

OpenCode 实际调用该命令，最终得到 `4 passed in 0.02s`。

## 五、项目 Agent

创建 `.opencode/agents/reviewer.md` 作为只读审查 Agent：

- 允许读取代码；
- 禁止编辑文件；
- 允许 `git status`、`git diff` 和 pytest；
- 其他终端命令需要询问。

项目根目录的 `AGENTS.md` 同时记录项目目标、目录结构、常用命令、开发规范和禁止操作，为 Agent 提供稳定上下文。

## 六、MCP 工具

创建本地 MCP Server：`tools/project_inspector_mcp.py`，提供两个工具：

- `project_summary`：返回项目摘要；
- `analyse_job_match`：调用项目匹配逻辑分析经历与 JD。

在 `opencode.json` 中启用 `project_inspector`。执行 `opencode mcp list` 后状态为 `connected`。OpenCode 实际调用 `project_inspector_project_summary`，返回：

```text
AI Job Copilot 是一个 Flask 岗位匹配 MVP；当前包含 1 个测试文件，并使用 pytest、Docker 和 Git 管理。
```

另外预留 Playwright MCP 配置，但默认设为 `enabled: false`，避免实验过程中自动下载额外依赖；需要浏览器自动化时再启用。

## 七、权限控制验证

`opencode.json` 设置三档权限：

| 类型 | 示例 | 实测结果 |
|---|---|---|
| allow | `.venv/bin/python -m pytest -q` | 自动执行，4 项测试通过 |
| ask | `git log -1 --oneline` | 出现 `permission requested`，未授权时自动拒绝 |
| deny | `git push` | 规则直接阻止，命令没有执行 |

高风险的 `rm *` 和 `git push*` 被明确禁止；未知终端命令默认询问，测试、状态检查等安全命令可自动运行。
